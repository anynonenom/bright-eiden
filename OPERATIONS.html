1. Local Development

Running the app on your Mac for development

1 Start the app locally

Why: Runs the Django app + PostgreSQL inside Docker on your Mac so you can develop without installing Python or Postgres manually.
Local Mac 
cd /Users/mac/Desktop/Eiden-web-apps/brightbean-studio
docker compose up -d

App runs at http://localhost:8000

2 Stop the app

Local Mac 
docker compose down

3 Restart after code changes

Why: Django's dev server auto-reloads Python files, but if you change .env or docker-compose files you need a full restart.
Local Mac 
# For .py / .html changes — auto-reloads, no action needed

# For .env or docker-compose changes:
docker compose up -d

4 View logs

Local Mac 
# All services
docker compose logs -f

# Just the app
docker compose logs -f app

# Just the background worker
docker compose logs -f worker

5 Run database migrations after model changes

Why: Every time you change a Django model (add field, create model) you must create and apply a migration so the database schema updates.
Local Mac 
docker compose exec app python manage.py makemigrations
docker compose exec app python manage.py migrate

6 Create a local admin account

Local Mac 
docker compose exec app python manage.py createsuperuser

7 Rebuild Docker image (after adding Python packages)

Why: If you add a new package to requirements.txt, the Docker image must be rebuilt so it's installed inside the container.
Local Mac 
docker compose build
docker compose up -d

2. First-Time Deployment to Oracle Cloud

How we deployed to the OCI VM at 130.61.245.119

1 Copy SSH key and set permissions

Why: SSH keys must have permission 600 (owner read/write only) or SSH refuses to use them for security reasons.
Local Mac 
cp ~/Downloads/ssh-key-2026-05-04.key ~/.ssh/oci_brightbean.key
chmod 600 ~/.ssh/oci_brightbean.key

2 SSH into the server

Local Mac 
ssh -i ~/.ssh/oci_brightbean.key opc@130.61.245.119

Note: Oracle Linux uses opc as the default user, not ubuntu.

3 Install Docker on Oracle Linux

Why: Oracle Linux uses dnf (not apt). We add Docker's official RHEL repo then install.
On Server 
sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable docker --now
sudo usermod -aG docker opc

4 Install rsync on server

On Server 
sudo dnf install -y rsync

5 Fix Docker DNS

Why: Oracle Linux's default DNS (127.0.0.53) doesn't work inside Docker containers. We tell Docker to use Google DNS (8.8.8.8) so containers can reach the internet (needed for Let's Encrypt SSL).
On Server 
echo '{"dns": ["8.8.8.8", "8.8.4.4"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker

6 Open firewall ports on Oracle Linux

Why: Oracle Linux uses firewalld (not UFW). We need ports 80 (HTTP) and 443 (HTTPS) open at the OS level.
On Server 
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --permanent --add-port=443/udp
sudo firewall-cmd --reload
Also required: In OCI Console → Networking → Virtual Cloud Networks → Security Lists → Add Ingress Rules for TCP port 80 and TCP port 443 with Source CIDR 0.0.0.0/0 and Source Port Range left blank.

7 Sync project files from Mac to server

Why: rsync efficiently copies only changed files. We exclude .git, __pycache__, and .env since they shouldn't be on the server.
Local Mac 
rsync -az \
  -e "ssh -i ~/.ssh/oci_brightbean.key -o StrictHostKeyChecking=no" \
  --exclude='.git' --exclude='__pycache__' --exclude='*.pyc' \
  --exclude='.env' --exclude='media/' --exclude='staticfiles/' \
  /Users/mac/Desktop/Eiden-web-apps/brightbean-studio/ \
  opc@130.61.245.119:/opt/brightbean/

8 Create production .env on server

On Server 
cp /opt/brightbean/.env.production /opt/brightbean/.env

9 Build Docker images on server

Why: The server builds its own Docker image from the Dockerfile. This installs all Python packages inside the container.
On Server 
cd /opt/brightbean
sudo docker compose -f docker-compose.oci.yml build

10 Run migrations and start all services

Why: Migrations create all database tables. We run them before starting the app so the app doesn't crash on missing tables.
On Server 
cd /opt/brightbean

# Start database first
sudo docker compose -f docker-compose.oci.yml up -d postgres
sleep 10

# Run migrations
sudo docker compose -f docker-compose.oci.yml run --rm --no-deps migrate

# Collect static files
sudo docker compose -f docker-compose.oci.yml run --rm --no-deps collectstatic

# Start everything
sudo docker compose -f docker-compose.oci.yml up -d app worker maintenance caddy

11 Create admin superuser

On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml exec app python manage.py createsuperuser

12 Stop nginx (was blocking port 80)

Why: Oracle Linux ships with nginx pre-installed and running on port 80. We disable it so Caddy can use that port.
One-time only On Server 
sudo systemctl stop nginx
sudo systemctl disable nginx

3. Pushing Updates to Production

Every time you make changes and want to deploy them live

1 Sync changed files to server

Local Mac 
rsync -az \
  -e "ssh -i ~/.ssh/oci_brightbean.key -o StrictHostKeyChecking=no" \
  --exclude='.git' --exclude='__pycache__' --exclude='*.pyc' \
  --exclude='.env' --exclude='media/' --exclude='staticfiles/' \
  /Users/mac/Desktop/Eiden-web-apps/brightbean-studio/ \
  opc@130.61.245.119:/opt/brightbean/

2a If you only changed templates or Python files

Why: Template and Python changes don't need a rebuild — just restart gunicorn.
On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml restart app

2b If you added new static files (images, CSS, JS)

Why: Static files must be collected and hashed by WhiteNoise before the app can serve them. The copy+collectstatic approach works without rebuilding the image.
On Server 
# Copy the new file into the running container
sudo docker cp /opt/brightbean/static/img/yourfile.jpg brightbean-app-1:/app/static/img/yourfile.jpg

# Run collectstatic inside the app container
sudo docker exec brightbean-app-1 python manage.py collectstatic --noinput

# Restart app
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml restart app

2c If you added new Python packages to requirements.txt

Why: New packages must be installed inside the Docker image. This requires a full rebuild.
On Server 
cd /opt/brightbean
sudo docker compose -f docker-compose.oci.yml build
sudo docker compose -f docker-compose.oci.yml up -d --no-build app worker

2d If you changed database models

On Server 
cd /opt/brightbean
sudo docker compose -f docker-compose.oci.yml run --rm --no-deps migrate
sudo docker compose -f docker-compose.oci.yml restart app

4. SSL / Domain Setup

How HTTPS works with Caddy and Let's Encrypt

1 How SSL works automatically

Why: Caddy is the reverse proxy sitting in front of Django. It automatically gets a free SSL certificate from Let's Encrypt when it starts, as long as port 443 is open and DNS points to the server.

Caddy reads the APP_DOMAIN variable from .env, contacts Let's Encrypt, proves ownership via HTTP challenge on port 80, and installs the certificate. Renews automatically every 90 days.

2 Change to a real domain

On Server 
# Edit .env on server
nano /opt/brightbean/.env

# Change these lines:
APP_URL=https://yourdomain.com
ALLOWED_HOSTS=yourdomain.com,130.61.245.119,localhost
APP_DOMAIN=yourdomain.com

# Update Caddyfile
cat > /opt/brightbean/Caddyfile << 'EOF'
yourdomain.com {
    reverse_proxy app:8000
    encode zstd gzip
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Frame-Options "SAMEORIGIN"
        X-Content-Type-Options "nosniff"
        -Server
    }
}
EOF

# Clear old SSL data and restart Caddy
sudo docker rm -f brightbean-caddy-1
sudo docker volume rm brightbean_caddy_data brightbean_caddy_config
sudo docker compose -f docker-compose.oci.yml up -d --no-build caddy
sudo docker compose -f docker-compose.oci.yml restart app

3 Check SSL certificate status

On Server 
sudo docker logs brightbean-caddy-1 2>&1 | grep -E "obtain|certificate|issued|error"

5. Email (Resend)

Transactional email for invites, notifications

1 How email is configured

Email is sent via Resend (resend.com) using SMTP. These variables are in docker-compose.override.yml (local) and .env (production).

EMAIL_BACKEND_TYPE=smtp
EMAIL_HOST=smtp.resend.com
EMAIL_PORT=587
EMAIL_HOST_USER=resend
EMAIL_HOST_PASSWORD=re_your_api_key_here
EMAIL_USE_TLS=True
DEFAULT_FROM_EMAIL=onboarding@resend.dev  # or noreply@yourdomain.com once domain verified
Limitation: Without a verified domain in Resend, emails can only be sent to your own Resend account email. Verify your domain at resend.com/domains to send to anyone.

2 Test email from server

On Server 
sudo docker exec brightbean-app-1 python manage.py shell -c "
from django.core.mail import send_mail
send_mail('Test', 'Working!', 'onboarding@resend.dev', ['your@email.com'])
print('Sent')
"

6. Media & Storage

Where uploaded images and videos are stored

1 Current setup (local storage)

Why: STORAGE_BACKEND=local in .env means uploaded files go to /app/media/ inside the Docker container, mapped to the media_data Docker volume on the server. Files persist across restarts.

Media files are at: /var/lib/docker/volumes/brightbean_media_data/_data/ on the server.

2 Switch to OCI Object Storage (S3-compatible)

Why: Object Storage is better for production — files survive even if the VM is deleted, and can be served via CDN. OCI gives 20GB free.

Steps: OCI Console → Object Storage → Create Bucket → Profile → Customer Secret Keys → Generate. Then update .env:

STORAGE_BACKEND=s3
S3_ENDPOINT_URL=https://<namespace>.compat.objectstorage.eu-frankfurt-1.oraclecloud.com
S3_ACCESS_KEY_ID=your_access_key
S3_SECRET_ACCESS_KEY=your_secret
S3_BUCKET_NAME=brightbean-media
S3_REGION_NAME=eu-frankfurt-1
# Then restart app
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml restart app worker

7. Admin Tasks

Common management commands

1 Check all containers are running

On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml ps

You should see 5 containers: app, worker, postgres, caddy, maintenance — all Up.

2 View live app logs

On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml logs -f app

3 Restart all services

On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml restart

4 Stop everything

On Server 
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml down

5 App starts automatically on server reboot

Why: We registered a systemd service called brightbean that runs docker compose up automatically when the VM boots.
On Server 
# Check status
sudo systemctl status brightbean

# Manually start/stop
sudo systemctl start brightbean
sudo systemctl stop brightbean

6 Open Django shell

On Server 
sudo docker exec -it brightbean-app-1 python manage.py shell

On Server 
sudo docker exec brightbean-postgres-1 pg_dump -U brightbean brightbean > backup_$(date +%Y%m%d).sql

8 Restore the database

On Server 
sudo docker exec -i brightbean-postgres-1 psql -U brightbean brightbean < backup_20260508.sql

8. Troubleshooting

Common problems and their fixes

App won't start — check logs first

sudo docker logs brightbean-app-1 2>&1 | tail -30

SSL certificate not issuing

Caddy can't get a cert if port 443 is blocked or the domain doesn't resolve to the server.
# Check OCI Security List has port 443 open (source port blank, dest port 443)
# Check DNS resolves: nslookup brightbean.mooo.com 8.8.8.8

# Clear Caddy data and retry:
sudo docker rm -f brightbean-caddy-1
sudo docker volume rm brightbean_caddy_data brightbean_caddy_config
cd /opt/brightbean
sudo docker compose -f docker-compose.oci.yml up -d --no-build caddy

Port 80 already in use

Oracle Linux ships with nginx running on port 80. Stop it so Caddy can use the port.
sudo systemctl stop nginx
sudo systemctl disable nginx

Migration error: "relation already exists"

Happens when a previous migration run was interrupted mid-way, leaving partial tables.
# Only if this is a fresh deployment with no real data:
sudo docker exec brightbean-postgres-1 psql -U brightbean postgres -c \
  "DROP DATABASE brightbean; CREATE DATABASE brightbean;"
sudo docker compose -f docker-compose.oci.yml run --rm --no-deps migrate

Browser says "server not found"

Your local ISP's DNS hasn't propagated the new domain yet. Use Google's DNS temporarily.

Mac: System Settings → Network → your connection → Details → DNS → add 8.8.8.8

Image uploads not working

Django 4.2+ requires an explicit STORAGES["default"] key. Without it, all file uploads raise InvalidStorageError.
# In config/settings/base.py, make sure this exists in the local storage branch:
STORAGES["default"] = {
    "BACKEND": "django.core.files.storage.FileSystemStorage",
}

New static files not appearing in production

WhiteNoise serves files from /app/staticfiles/ inside the container. New files must be copied in and collectstatic re-run.
# Copy file into running container
sudo docker cp /opt/brightbean/static/img/newfile.jpg brightbean-app-1:/app/static/img/newfile.jpg

# Collect inside container
sudo docker exec brightbean-app-1 python manage.py collectstatic --noinput

# Restart
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml restart app

Containers not picking up .env changes

docker compose restart does NOT reload environment variables. You must recreate the container.
sudo docker compose -f /opt/brightbean/docker-compose.oci.yml up -d --no-build app
